① 文書の構造 — DOM（Document Object Model）

重要ポイント①：DOMをJavaScriptで操作し、文書を取得・変更したり、要素の値を動的に変更することが可能
DOM（Document Object Model）は、HTMLやXML文書を ツリー構造のオブジェクトとして表現する仕様です。 JavaScriptから DOM を操作することで、 要素の取得・追加・削除・属性変更・テキスト変更などを 動的に行えます。

DOM ツリーの構造

Document（ルートノード）
└── <html>
    ├── <head>
    │   └── <title> ページタイトル </title>
    └── <body>
        ├── <h1 id="title"> 見出し </h1>
        └── <p class="text"> 本文テキスト </p>

主な DOM 操作メソッド

getElementById()
IDで要素を1つ取得する
querySelector()
CSSセレクタで最初の要素を取得する
querySelectorAll()
CSSセレクタで一致するすべての要素を取得する
createElement()
新しい要素ノードを作成する
appendChild()
子要素として末尾に追加する
removeChild()
子要素を削除する
setAttribute()
要素の属性を設定する
textContent
要素のテキスト内容を取得・設定する
innerHTML
要素のHTML内容を取得・設定する（XSSに注意）
classList
クラスの追加・削除・切り替えを行う
/* 要素の取得 */
const el1 = document.getElementById('title');
const el2 = document.querySelector('.text');
const els = document.querySelectorAll('p');

/* テキスト・属性の変更 */
el1.textContent = '新しい見出し';
el1.setAttribute('class', 'highlight');
el1.style.color = '#086f83';

/* クラスの操作 */
el1.classList.add('active');
el1.classList.remove('hidden');
el1.classList.toggle('open');

/* 要素の作成・追加 */
const newEl = document.createElement('li');
newEl.textContent = '新しいリスト項目';
document.querySelector('ul').appendChild(newEl);

/* イベントリスナーの登録 */
el1.addEventListener('click', (e) => {
  console.log('クリックされました', e.target);
});

② JavaScript

重要ポイント②：JavaScriptはプロトタイプベースのオブジェクト指向型言語で、主要なWebブラウザに実装されている
JavaScript は ECMAScript 仕様に基づく、 プロトタイプベースのオブジェクト指向型スクリプト言語です。 主要なWebブラウザにJavaScriptエンジンが実装されており、 クライアントサイドでの動的なWebページ制作に不可欠です。 現在は Node.js によりサーバーサイドでも広く使われています。

JavaScriptの主な特徴

プロトタイプベース
クラスベースではなくプロトタイプチェーンによって オブジェクトが継承を実現する。 ES6以降は class 構文も使用可能（内部はプロトタイプ）
動的型付け
変数の型を宣言する必要がなく、 実行時に型が決まる。 typeof 演算子で型を確認できる
シングルスレッド
JavaScriptはシングルスレッドで動作する。 非同期処理はイベントループ・Promise・ async/await で実現する
ECMAScript
JavaScriptの仕様は ECMA International の TC39 委員会が管理する ECMAScript として標準化されている
ファーストクラス関数
関数を変数に代入したり、 引数として渡したり、 戻り値として返すことができる
クロージャ
関数が定義されたスコープの変数を 関数の外からでも参照し続けられる仕組み 
/* プロトタイプベースの継承 */
function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function() {
  return `${this.name} が鳴きます`;
};

/* ES6 class 構文（内部はプロトタイプ） */
class Dog extends Animal {
  speak() {
    return `${this.name}: ワン！`;
  }
}
const dog = new Dog('ポチ');
console.log(dog.speak()); // "ポチ: ワン！"

/* 動的型付け */
let x = 42;          // number
x = 'hello';         // string（再代入可能）
x = true;            // boolean
console.log(typeof x); // "boolean"

/* 非同期処理（Promise / async-await） */
async function fetchData() {
  const res  = await fetch('/api/data');
  const data = await res.json();
  return data;
}

④ 通信 — Ajax

重要ポイント③：Ajaxにより、非同期通信と動的ページ書き換えを実現する
Ajax（Asynchronous JavaScript and XML）は、 ページ全体を再読み込みせずに サーバーと非同期通信を行い、 DOMを動的に書き換える技術です。 XHR（XMLHttpRequest）または Fetch API を使って実装します。 現代の SPA（Single Page Application）の基盤技術です。

従来のWebとAjaxの比較

項目従来のWeb（ページ遷移）Ajax（非同期通信）
通信タイミングリンクやフォーム送信のたびに全ページ取得必要なデータのみ非同期で取得
ページ更新ページ全体を再読み込み必要な部分のみDOMを書き換え
ユーザー体験画面が白くなる・待ち時間が長いスムーズ・レスポンシブな操作感
サーバー負荷毎回HTML全体を生成・送信必要なデータ（JSON等）のみ送受信

Ajax の仕組み

ブラウザ（クライアント）
① ユーザー操作
② XHR / fetch() でリクエスト
⑤ コールバック実行
⑥ DOM を部分更新
非同期 ↔ HTTP
Webサーバー
③ リクエスト受信
④ JSON / XML で
   データを返す 
/* Ajax の基本（Fetch API を使用） */
async function loadData() {
  try {
    /* ① 非同期でサーバーにリクエスト */
    const res  = await fetch('/api/users');
    const data = await res.json();

    /* ② ページ全体を再読み込みせずにDOMを更新 */
    const list = document.getElementById('user-list');
    list.innerHTML = '';
    data.forEach(user => {
      const li = document.createElement('li');
      li.textContent = user.name;
      list.appendChild(li);
    });
  } catch (e) {
    console.log('エラー:', e);
  }
}

/* ボタンクリックで非同期通信（ページ遷移なし） */
document.getElementById('load-btn')
  .addEventListener('click', loadData);

⑤ Webサイトへの不正な攻撃手法

XSS（クロスサイトスクリプティング）
悪意のあるスクリプトをWebページに埋め込み、 閲覧者のブラウザで実行させる攻撃。 Cookie窃取・フィッシングなどに悪用される。
CSRF（クロスサイトリクエストフォージェリ）
ユーザーが意図しないリクエストを ログイン済みサイトに送信させる攻撃。 パスワード変更・送金などを不正実行。
SQLインジェクション
入力フォームにSQL文を埋め込み、 データベースを不正操作する攻撃。 データ漏洩・改ざん・削除が発生する。
クリックジャッキング
透明なiframeを重ねて、 ユーザーが意図しないボタンを クリックさせる攻撃。
DDoS攻撃
大量のリクエストをサーバーに送り、 サービスを停止させる攻撃。 分散型（Distributed）で行われる。
中間者攻撃（MITM）
通信経路に割り込み、 データを盗聴・改ざんする攻撃。 HTTPSで防止できる。

⑥ ネットワーク上の脅威対策

XSS対策
・入力値のエスケープ処理（< → &lt;）
・Content Security Policy（CSP）でスクリプト実行を制限
・Cookie に HttpOnly 属性を設定
・innerHTML の使用を避け textContent を使う
CSRF対策
・CSRFトークンをフォームに埋め込む
・Cookie に SameSite=Strict を設定
・Referer / Origin ヘッダーの検証
・重要操作に再認証を要求
SQLインジェクション対策
・プリペアドステートメント（パラメータ化クエリ）を使用
・入力値のバリデーション・サニタイズ
・DBアカウントの権限を最小化
HTTPS の使用
・TLS/SSL で通信を暗号化
・中間者攻撃・盗聴・改ざんを防止
・HSTS（HTTP Strict Transport Security）で強制HTTPS
Content Security Policy（CSP）
・HTTPヘッダーで読み込み可能なリソースを制限
・インラインスクリプトの実行を禁止
・XSS攻撃の被害を大幅に軽減
クリックジャッキング対策
・X-Frame-Options ヘッダーで iframe 埋め込みを禁止
・CSP の frame-ancestors ディレクティブを使用 
/* Content Security Policy（CSP）の設定例 */
/* HTTPレスポンスヘッダーで設定 */
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'

/* HTMLのmetaタグでも設定可能 */
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; script-src 'self'">

/* XSS対策：textContent でエスケープ */
/* ❌ 危険：innerHTML はXSSの原因になる */
el.innerHTML = userInput;

/* ✅ 安全：textContent はHTMLとして解釈されない */
el.textContent = userInput;

/* CSRF対策：CSRFトークンをフォームに埋め込む */
<form method="POST">
  <input type="hidden" name="csrf_token" value="ランダムなトークン">
  ...
</form>

⑧ 画像について

主な画像フォーマット

JPEG / JPG
非可逆圧縮。写真に最適。 透過・アニメーション不可。 ファイルサイズを小さくできる
PNG
可逆圧縮。透過（アルファチャンネル）対応。 ロゴ・イラストに最適。 JPEGより容量が大きくなりやすい
GIF
256色まで。アニメーション対応。 透過可能（1ビット）。 シンプルなアニメーションに使用
SVG
ベクター形式。拡大しても劣化しない。 CSSやJSで操作可能。 アイコン・ロゴに最適
WebP
Google開発。JPEG・PNGより高圧縮。 可逆・非可逆・透過・アニメーション対応。 モダンブラウザで広くサポート
AVIF
AV1ベースの次世代フォーマット。 WebPよりさらに高圧縮。 対応ブラウザが増加中

画像フォーマットの比較

形式圧縮透過アニメーション主な用途
JPEG非可逆❌❌写真・グラデーション
PNG可逆✅（アルファ）❌ロゴ・イラスト・透過画像
GIF可逆✅（1ビット）✅シンプルなアニメーション
SVGベクター✅✅（CSS/JS）アイコン・ロゴ・図形
WebP可逆・非可逆✅✅Web全般（高圧縮）

⑨ Webサイトの集客・収益

主な集客・収益化手法

SEO（検索エンジン最適化）
検索エンジンの検索結果で上位表示されるよう コンテンツ・構造・リンクを最適化する手法。 セマンティックなHTMLの使用が重要
SEM（検索エンジンマーケティング）
検索エンジンを活用したマーケティング全般。 SEO（自然検索）と リスティング広告（有料検索）を含む
SNSマーケティング
Twitter・Instagram・Facebook等の SNSを活用した集客・ブランディング手法。 シェアによる拡散効果が高い
アフィリエイト
Webサイトに広告リンクを掲載し、 クリックや購入に応じて報酬を得る 成果報酬型の収益化手法
Webアクセス解析
Google Analytics 等のツールで 訪問者数・行動・流入経路などを分析し、 サイト改善に活用する
OGP（Open Graph Protocol）
SNSでシェアされた際に タイトル・画像・説明文を 正しく表示するためのメタタグ仕様 
<!-- SEO・OGP のためのメタタグ例 -->
<head>
  <!-- SEO：ページの説明 -->
  <meta name="description"
        content="HTML5プロフェッショナル認定試験 レベル1 対策サイト">

  <!-- OGP：SNSシェア時の表示 -->
  <meta property="og:title"
        content="HTML5 / CSS 学習ノート">
  <meta property="og:description"
        content="試験合格を目指す学習用サンプル集">
  <meta property="og:image"
        content="https://example.com/ogp.png">
  <meta property="og:url"
        content="https://example.com/">
  <meta property="og:type"
        content="website">
</head>
