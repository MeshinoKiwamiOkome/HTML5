🎨 マルチメディア・グラフィックスAPI 学習サンプル

HTML5で強化されたマルチメディア制御・ストリーミング・グラフィックスに関するAPIの 概要と使い方を学びましょう。

① マルチメディア — HTMLMediaElement API

重要ポイント①：audio要素・video要素で埋め込んだマルチメディアコンテンツの再生を、JavaScriptで制御できる
<audio>・<video> 要素は HTMLMediaElement インターフェースを実装しており、 JavaScriptから再生・停止・音量・再生位置・再生速度などを プログラムで制御できます。 ユーザー操作なしに自動制御したり、カスタムUIを実装したりする際に使います。

HTMLMediaElement の主なプロパティ・メソッド・イベント

種別名前説明
メソッド play() 再生開始（Promiseを返す）
pause() 一時停止
load() メディアを再読み込み（src変更後に呼ぶ）
プロパティ currentTime 現在の再生位置（秒）。書き込みでシーク可能
duration メディアの総再生時間（秒）。読み取り専用
volume 音量（0.0〜1.0）
muted ミュート状態（true/false）
paused 一時停止中かどうか（読み取り専用）
playbackRate 再生速度（1.0が通常速度、2.0で2倍速）
loop ループ再生（true/false）
イベント play 再生開始時に発火
pause 一時停止時に発火
ended 再生終了時に発火
timeupdate 再生位置が変化するたびに発火（進捗バー更新などに利用） 
/* video / audio 要素を取得 */
const video = document.getElementById('myVideo');
const audio = document.getElementById('myAudio');

/* 再生・停止 */
video.play();    /* 再生（Promiseを返す） */
video.pause();   /* 一時停止 */

/* 音量・ミュート */
video.volume = 0.5;    /* 50%の音量（0.0〜1.0） */
video.muted  = true;   /* ミュート */

/* 再生位置・速度 */
video.currentTime  = 30;  /* 30秒の位置にシーク */
video.playbackRate = 1.5; /* 1.5倍速で再生 */

/* 再生状態の確認 */
if (video.paused) {
  video.play();
} else {
  video.pause();
}

/* イベントリスナー */
video.addEventListener('ended', () => {
  console.log('再生終了');
});
video.addEventListener('timeupdate', () => {
  /* 再生位置が変わるたびに呼ばれる（進捗バー更新など） */
  console.log(video.currentTime + ' / ' + video.duration);
});

⚠️ play() はPromiseを返す
モダンブラウザでは play() は Promise を返します。 オートプレイポリシーにより再生が拒否される場合があるため、 .catch() でエラーハンドリングすることが推奨されます。
video.play().catch(err => console.log('再生できません:', err));

② ストリーミング

重要ポイント：ストリーミングはメディアデータを分割して順次受信・再生する技術である
ストリーミングとは、動画・音声データをすべてダウンロードしてから再生するのではなく、 データを小さなチャンクに分割して順次受信しながら再生する技術です。 待ち時間を短縮し、長時間コンテンツでも即座に再生を開始できます。

プログレッシブダウンロード vs ストリーミング

方式仕組み特徴
プログレッシブダウンロード ファイルを先頭から順にダウンロードしながら再生 シンプル。ダウンロード済みの範囲のみシーク可能
ストリーミング データを細かく分割して順次配信・再生 即時再生・ライブ配信・画質の自動切替（アダプティブ）が可能

主なストリーミング技術

HLS（HTTP Live Streaming）
Appleが開発。動画を小さなセグメント（.ts / .m4s）に分割し、 プレイリストファイル（.m3u8）で管理。 iOSでネイティブサポート。
MPEG-DASH
ISO標準のアダプティブストリーミング規格。 MPDファイル（XML）でセグメントを管理。 YouTubeなどで採用。
MSE（Media Source Extensions）
JavaScriptからメディアデータを動的に <video> 要素に 供給できるAPI。HLS・DASHのブラウザ実装の基盤となる。
WebRTC
ブラウザ間でリアルタイムの音声・映像・データを P2Pで通信するAPI。 ビデオ通話・画面共有などに利用。

Media Source Extensions（MSE）の概要

/* MSE：JavaScriptからvideo要素にメディアデータを動的に供給する */
const video = document.getElementById('myVideo');
const ms    = new MediaSource();

/* MediaSourceオブジェクトをvideo要素のsrcに設定 */
video.src = URL.createObjectURL(ms);

/* sourceopen イベント：SourceBufferを追加してデータを供給 */
ms.addEventListener('sourceopen', () => {
  const sb = ms.addSourceBuffer('video/mp4; codecs="avc1.42E01E,mp4a.40.2"');

  /* fetchでセグメントデータを取得してSourceBufferに追加 */
  fetch('segment1.mp4')
    .then(res => res.arrayBuffer())
    .then(buf => sb.appendBuffer(buf));
});

video 要素でのストリーミング再生（HLS の例）

<!-- iOSはHLSをネイティブサポート -->
<video src="stream.m3u8" controls></video>

<!-- PCブラウザではhls.jsなどのライブラリを使う -->
<script src="hls.js"></script>
<script>
  if (Hls.isSupported()) {
    const hls = new Hls();
    hls.loadSource('stream.m3u8');
    hls.attachMedia(video);
  }
</script>
✅ 試験でのポイント
・ストリーミングはデータを分割して順次受信しながら再生する技術
・MSE（Media Source Extensions）はJavaScriptからメディアデータを 動的に <video> 要素に供給するAPIで、HLS・DASHのブラウザ実装の基盤
・<video>・<audio> 要素はストリーミングコンテンツも再生できる

③ Canvas API（グラフィックス）

重要ポイント②：Canvas(2D)はJavaScriptでビットマップ形式の画像を描画する
<canvas> 要素はピクセルベースの描画領域を提供します。 JavaScriptで getContext('2d') を呼び出して取得した 2Dレンダリングコンテキストを通じて、図形・テキスト・画像などを描画します。 描画結果はビットマップ（ラスター）形式として扱われ、 拡大すると粗くなります。

Canvas APIの基本メソッド

fillRect(x,y,w,h)
塗りつぶした矩形を描画。fillStyle で色を指定
strokeRect(x,y,w,h)
枠線のみの矩形を描画。strokeStyle で色を指定
arc(x,y,r,start,end)
円弧を描画。beginPath()・fill()/stroke() と組み合わせる
moveTo / lineTo
パスの移動・直線の追加。stroke() で描画確定
fillText(text,x,y)
テキストを塗りつぶして描画。font プロパティで書体指定
drawImage(img,x,y)
画像・video・他のcanvasを描画。サイズ変更も可能
clearRect(x,y,w,h)
指定範囲を消去（透明にする）
save() / restore()
描画状態（色・変換行列など）の保存・復元
<!-- HTMLでcanvas要素を定義 -->
<canvas id="myCanvas" width="400" height="200"></canvas>

/* JavaScriptで2Dコンテキストを取得して描画 */
const canvas = document.getElementById('myCanvas');
const ctx    = canvas.getContext('2d');  /* 2Dレンダリングコンテキスト取得 */

/* 矩形の描画 */
ctx.fillStyle = '#f6ad55';
ctx.fillRect(20, 20, 100, 60);          /* 塗りつぶし矩形 */
ctx.strokeStyle = '#c05621';
ctx.lineWidth   = 3;
ctx.strokeRect(140, 20, 100, 60);       /* 枠線矩形 */

/* 円の描画 */
ctx.beginPath();
ctx.arc(300, 50, 40, 0, Math.PI * 2);  /* x, y, 半径, 開始角, 終了角 */
ctx.fillStyle = '#68d391';
ctx.fill();

/* テキストの描画 */
ctx.font      = 'bold 20px sans-serif';
ctx.fillStyle = '#2d3748';
ctx.fillText('Canvas!', 20, 120);

/* パス（直線）の描画 */
ctx.beginPath();
ctx.moveTo(20, 150);
ctx.lineTo(380, 150);
ctx.strokeStyle = '#9f7aea';
ctx.lineWidth   = 2;
ctx.stroke();

⚠️ Canvas の注意点
・<canvas> の width・height 属性はCSS指定とは別物です。 CSSでサイズを変えると描画が引き伸ばされます
・描画結果はビットマップ形式のため、拡大すると粗くなります（SVGと異なる点）
・アクセシビリティのため、<canvas> 内にフォールバックコンテンツを記述できます

④ SVG（グラフィックス）

重要ポイント③：SVGはHTMLにインライン記述可能なベクター形式の画像フォーマットである
SVG（Scalable Vector Graphics）はXMLベースのベクター形式の画像フォーマットです。 HTMLに直接インラインで埋め込むことができ（インラインSVG）、 数式で図形を定義するためどんなサイズに拡大しても鮮明に表示されます。 CSSでスタイルを適用でき、JavaScriptでDOMとして操作することも可能です。

Canvas vs SVG の比較

項目Canvas（2D）SVG
形式ビットマップ（ラスター）ベクター
拡大時粗くなる劣化しない
HTMLへの記述<canvas> 要素インライン記述可能（<svg>〜</svg>）
DOM操作不可（ピクセル単位）可能（要素として操作）
イベント座標で判定が必要要素に直接付与可能
向いている用途ゲーム・動画処理・複雑な描画アイコン・チャート・ロゴ

SVGのインライン記述とHTMLへの組み込み方法

<!-- ① インラインSVG：HTMLに直接埋め込む（最も柔軟） -->
<svg width="200" height="100" xmlns="http://www.w3.org/2000/svg">
  <rect    x="10"  y="10"  width="80"  height="50"  fill="#f6ad55" />
  <circle  cx="150" cy="35" r="30"                  fill="#9f7aea" />
  <line    x1="10" y1="80" x2="190" y2="80"     stroke="#68d391" stroke-width="3" />
  <text    x="10"  y="95"  font-size="14"              fill="#2d3748">SVG Text</text>
</svg>

<!-- ② img要素で外部SVGファイルを読み込む -->
<img src="logo.svg" alt="ロゴ">

<!-- ③ CSSのbackground-imageで使う -->
.icon { background-image: url('icon.svg'); }

/* インラインSVGはCSSやJavaScriptで操作可能 */
const circle = document.querySelector('circle');
circle.setAttribute('fill', '#f6ad55'); /* 色をJSで変更 */

✅ 試験でのポイント
・SVGはHTMLにインライン記述できる（<svg>〜</svg> をHTMLに直接書ける）
・SVGはベクター形式のため、拡大・縮小しても画質が劣化しない
・インラインSVGの各要素はDOMノードとして扱われ、CSSやJavaScriptで操作できる
・<img src="logo.svg"> でも読み込めるが、この場合はDOM操作不可

⑤ WebGL（概要）

重要ポイント：WebGLはcanvas要素上でOpenGL ES 2.0ベースの3Dグラフィックスを描画するAPI
WebGLは <canvas> 要素に対して getContext('webgl') または getContext('webgl2') を呼び出すことで利用できます。 GPU を活用した高性能な3Dグラフィックスをブラウザ上で実現します。 
/* WebGLコンテキストの取得 */
const canvas = document.getElementById('myCanvas');

/* 2Dコンテキスト（Canvas API） */
const ctx = canvas.getContext('2d');

/* WebGL 1.0（3Dグラフィックス） */
const gl  = canvas.getContext('webgl');

/* WebGL 2.0（より多機能） */
const gl2 = canvas.getContext('webgl2');

/* 非対応チェック */
if (!gl) {
  console.log('WebGLはこのブラウザでは利用できません');
}
✅ 試験でのポイント
・WebGLは <canvas> 要素を使う（専用の要素ではない）
・getContext('webgl') でコンテキストを取得する
・OpenGL ES 2.0 をベースにしたAPIである
・2DはCanvas API（'2d'）、3DはWebGL（'webgl'）と使い分ける
