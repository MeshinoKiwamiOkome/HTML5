① Fluid Grid（可変グリッド）

Fluid Grid とは、レイアウトの幅を固定値（px）ではなく相対単位（%）で指定する手法です。 コンテナの幅が変わると、各カラムの幅も自動的に比率を保ちながら変化します。

固定グリッド vs 可変グリッドの違い

❌ 固定グリッド（px指定）
200px
200px
画面が狭くなっても幅は変わらない → はみ出す
✅ 可変グリッド（%指定）
48%
48%
画面幅に応じて自動的に幅が変わる → はみ出さない 
/* ===== 固定グリッド（非推奨） ===== */
.container { width: 960px; }        /* 固定幅 */
.column    { width: 300px; float: left; } /* 固定幅カラム */

/* ===== Fluid Grid（推奨） ===== */
.container {
  width: 100%;
  max-width: 960px;  /* 最大幅は設定しておく */
  margin: 0 auto;
}
.column { width: 33.333%; }  /* %で指定 */

/* ===== px → % への変換式 ===== */
/* % = 要素の幅(px) ÷ 親要素の幅(px) × 100 */
/* 例：300px ÷ 960px × 100 = 31.25% */
.column { width: 31.25%; }

/* ===== CSS Grid を使った Fluid Grid ===== */
.container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);  /* 3等分 */
  gap: 20px;
}

/* ===== Flexbox を使った Fluid Grid ===== */
.container { display: flex; flex-wrap: wrap; gap: 20px; }
.column    { flex: 1 1 calc(33.333% - 20px); }

② Fluid Image（可変イメージ）

重要ポイント①：Fluid Image（可変イメージ）は、画像幅をウィンドウ幅に合わせて変更する手法
画像に max-width: 100% を指定することで、 コンテナの幅を超えずに自動的にリサイズされます。 縦横比を維持するために height: auto もあわせて指定します。 
/* ===== Fluid Image の基本 ===== */
img {
  max-width: 100%;  /* コンテナ幅を超えない */
  height: auto;     /* 縦横比を自動維持 */
}

/* ===== width: 100% との違い ===== */
img { width: 100%; }      /* 常にコンテナ幅いっぱいに引き伸ばされる */
img { max-width: 100%; } /* 元のサイズを超えない・コンテナより小さければそのまま */

/* ===== 動画・iframe にも同様に適用 ===== */
video, iframe, embed, object {
  max-width: 100%;
  height: auto;
}

/* ===== object-fit で画像の表示方法を制御 ===== */
.thumbnail {
  width: 100%;
  height: 200px;
  object-fit: cover;    /* 縦横比を保ちながらトリミング */
  object-position: center;
}

/* ===== picture 要素でデバイスに応じた画像を切り替え ===== */

<picture>
  <source
    srcset="large.jpg"
    media="(min-width: 769px)">
  <source
    srcset="medium.jpg"
    media="(min-width: 601px)">
  <img src="small.jpg" alt="説明"
       style="max-width:100%; height:auto;">
</picture>

Fluid Image インタラクティブデモ

400px
元の画像サイズ：500px × 200px
/* コンテナ幅: 400px / 元画像幅: 500px */ img { max-width: 100%; height: auto; } /* → 表示幅: 400px（コンテナに収まる）*/
⚠️ width: 100% と max-width: 100% の違い
・width: 100%：元の画像サイズより小さいコンテナでも、常にコンテナ幅いっぱいに引き伸ばされます
・max-width: 100%：コンテナより大きい場合はコンテナ幅に収まりますが、 コンテナより小さい場合は元のサイズのまま表示されます
→ Fluid Image には max-width: 100% が推奨です

③ ビューポート（viewport）

重要ポイント②：「ビューポート」とはブラウザの表示領域で、HTMLの meta 要素で指定する
ビューポートとは、Webページが表示されるブラウザの表示領域のことです。 スマートフォンのブラウザはデフォルトで「仮想ビューポート（980px程度）」を使うため、 <meta name="viewport"> で表示幅を指定しないと PC用のレイアウトが縮小表示されてしまいます。

viewport メタタグがない場合とある場合の違い

❌ viewport 指定なし
← PC用レイアウト（960px幅）が縮小表示 →
スマホ画面（375px）
PC幅で描画→縮小
✅ viewport 指定あり
デバイス幅（375px）で
最適表示
スマホ画面（375px）
デバイス幅で描画
<!-- 基本的な viewport 指定（head 内に記述） -->
<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

<!-- content 属性の各値の意味 -->
width=device-width    : ビューポート幅をデバイスの画面幅に合わせる
initial-scale=1.0     : 初期ズーム倍率を1.0（等倍）にする
minimum-scale=1.0     : 最小ズーム倍率（省略可）
maximum-scale=1.0     : 最大ズーム倍率（ユーザーのズームを禁止・非推奨）
user-scalable=no      : ユーザーのズーム操作を禁止（アクセシビリティ上非推奨）
viewport-fit=cover    : ノッチ付きデバイスの安全領域を考慮

viewport の content 属性の値

値説明推奨
width=device-width ビューポート幅をデバイスの画面幅に設定 ✅ 必須
initial-scale=1.0 初期ズーム倍率を等倍（1.0）に設定 ✅ 必須
minimum-scale=1.0 最小ズーム倍率を設定 ⚠️ 省略可
maximum-scale=1.0 最大ズーム倍率を設定（ズームを制限） ❌ 非推奨（アクセシビリティ問題）
user-scalable=no ユーザーのピンチズームを禁止 ❌ 非推奨（アクセシビリティ問題）
viewport-fit=cover ノッチ・ホームバーなどの安全領域を考慮 ⚠️ 必要に応じて
⚠️ user-scalable=no / maximum-scale=1.0 は非推奨
ユーザーのズーム操作を禁止することは、 視覚障害のあるユーザーや高齢者のアクセシビリティを著しく損ないます。 WCAG（Webコンテンツアクセシビリティガイドライン）でも ズームを無効にしないことが推奨されています。

CSS の viewport 単位（vw / vh / vmin / vmax）

/* vw：ビューポートの幅の1% */
.hero      { width: 100vw; }   /* ビューポート幅いっぱい */
.font-fluid{ font-size: 4vw; }  /* 画面幅に応じてフォントサイズが変わる */

/* vh：ビューポートの高さの1% */
.full-screen{ height: 100vh; }  /* 画面の高さいっぱい */
.half-screen{ height: 50vh; }   /* 画面の高さの半分 */

/* vmin：vw と vh の小さい方の1% */
.square { width: 50vmin; height: 50vmin; }

/* vmax：vw と vh の大きい方の1% */
.cover  { width: 100vmax; }

vw / vh インタラクティブデモ

3vw
ビューポートに応じて文字サイズが変わります
font-size: 3vw; /* ビューポート幅が 960px の場合 → 28.8px */

④ リセットCSS（Reset CSS）

重要ポイント③：リセットCSSは、Webブラウザに設定されているデフォルトのCSSを揃えるもの
各ブラウザはデフォルトのスタイルシート（UA スタイルシート）を持っており、 ブラウザによって微妙に異なります。 リセットCSSを使うことで、ブラウザ間の表示の差異をなくし、 一貫したスタイルを適用できます。

ブラウザのデフォルトスタイルの例

❌ リセットCSSなし（ブラウザデフォルト）

h1 要素

p 要素（上下に margin あり）

  • リスト項目（左 padding あり）
リンク（青・下線）
✅ リセットCSSあり（均一化後）

h1 要素（margin・サイズリセット）

p 要素（margin なし）

  • リスト項目（マーカー・padding なし）
リンク（色・下線リセット）

リセットCSSの種類

種類特徴代表例
リセットCSS ブラウザのデフォルトスタイルをすべてゼロにリセットする Eric Meyer's Reset CSS
ノーマライズCSS デフォルトスタイルをブラウザ間で統一する（有用なデフォルトは残す） Normalize.css
サニタイズCSS ノーマライズをベースにより現代的なベストプラクティスを適用 sanitize.css

代表的なリセットCSSのコード

/* ===== Eric Meyer's Reset CSS（抜粋） ===== */
/* すべての要素のマージン・パディング・ボーダーをゼロにリセット */
html, body, div, span, h1, h2, h3, h4, h5, h6, p,
blockquote, pre, a, abbr, em, img, ol, ul, li,
table, caption, tbody, tfoot, thead, tr, th, td {
  margin: 0;
  padding: 0;
  border: 0;
  font-size: 100%;
  font: inherit;
  vertical-align: baseline;
}
body { line-height: 1; }
ol, ul { list-style: none; }
table { border-collapse: collapse; border-spacing: 0; }

/* ===== 現代的なミニリセット（よく使われる最小限のリセット） ===== */
*, *::before, *::after {
  box-sizing: border-box;  /* ボックスモデルを統一 */
  margin: 0;
  padding: 0;
}
body {
  line-height: 1.5;
  -webkit-font-smoothing: antialiased;
}
img, picture, video, canvas, svg {
  display: block;
  max-width: 100%;  /* Fluid Image も同時に設定 */
}
input, button, textarea, select {
  font: inherit;  /* フォームのフォントをページに合わせる */
}
p, h1, h2, h3, h4, h5, h6 {
  overflow-wrap: break-word;
}
✅ 現代のベストプラクティス
現在は Normalize.css や 現代的なミニリセット（上記）が広く使われています。 box-sizing: border-box をすべての要素に適用することで、 パディングを含めたボックスサイズの計算が直感的になります。 また img { max-width: 100%; } を含めることで Fluid Image の設定も同時に行えます。

リセットCSSの適用方法

<!-- 方法①：外部ファイルとして読み込む（最初に読み込む） -->
<link rel="stylesheet" href="reset.css">
<link rel="stylesheet" href="style.css">

<!-- 方法②：CDN から Normalize.css を読み込む -->
<link rel="stylesheet"
      href="https://cdnjs.cloudflare.com/ajax/libs/normalize/8.0.1/normalize.min.css">

<!-- 方法③：自分のCSSファイルの先頭に直接書く -->
/* reset.css の内容をそのまま style.css の先頭に記述 */
⚠️ リセットCSSは必ず先頭で読み込む
リセットCSSは自分のスタイルより前に読み込む必要があります。 後から読み込むと、自分のスタイルがリセットされてしまいます。 CSSのカスケードでは後から書いたスタイルが優先されるためです。
