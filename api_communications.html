🔌 通信系API 学習サンプル

HTML5で追加・強化されたブラウザの通信系APIの概要と使い方を学びましょう。 HTTP通信・双方向通信・サーバーからのプッシュ・ブラウザ間のリアルタイム通信を扱います。

通信方式の全体比較

API通信方向接続方式主な用途
XHR / Fetch クライアント → サーバー（リクエスト/レスポンス） HTTP（都度接続） REST API呼び出し・フォーム送信
Server-Sent Events サーバー → クライアント（一方向） HTTP（持続接続） 通知・株価・ニュースフィード
WebSocket 双方向（全二重） ws:// / wss://（持続接続） チャット・ゲーム・リアルタイム共同編集
WebRTC ブラウザ間（P2P） P2P（サーバー経由なし） ビデオ通話・音声通話・ファイル共有

① XMLHttpRequest（XHR）/ Fetch API

重要ポイント①：XMLHttpRequestでHTTP通信を実現する
XMLHttpRequest（XHR）はブラウザからHTTPリクエストを送受信するAPIです。 ページ全体を再読み込みせずにサーバーとデータをやり取りする Ajax（Asynchronous JavaScript and XML）の基盤技術です。 現在はより簡潔な Fetch API（Promiseベース）が主流ですが、 XHRは進捗取得など一部の場面で今も使われます。

XHR の readyState（状態遷移）

0UNSENT
未初期化
1OPENED
open()呼出済
2HEADERS_RECEIVED
ヘッダー受信済
3LOADING
受信中
4DONE
完了

XHR の主なプロパティ・メソッド・イベント

open(method, url)
リクエストを初期化。メソッド（GET/POST等）とURLを指定
send(body)
リクエストを送信。POSTの場合はbodyにデータを渡す
setRequestHeader()
リクエストヘッダーを設定。open()の後に呼ぶ
abort()
リクエストを中断する
readyState
現在の状態（0〜4）。4（DONE）で完了
status / statusText
HTTPステータスコード（200, 404等）とテキスト
responseText / responseXML
レスポンスをテキスト / XMLとして取得
onreadystatechange
readyState が変化するたびに呼ばれるコールバック
onprogress
受信の進捗を取得できる（Fetchにはない機能）
timeout
タイムアウト時間（ms）を設定できる
/* ===== XMLHttpRequest（XHR）===== */
const xhr = new XMLHttpRequest();

/* リクエストの初期化 */
xhr.open('GET', 'https://api.example.com/data', true); /* true=非同期 */

/* ヘッダーの設定（open()の後に行う） */
xhr.setRequestHeader('Content-Type', 'application/json');

/* タイムアウト設定 */
xhr.timeout = 5000; /* 5秒 */

/* readyState の変化を監視 */
xhr.onreadystatechange = function() {
  if (xhr.readyState === 4) {          /* DONE */
    if (xhr.status === 200) {
      const data = JSON.parse(xhr.responseText);
      console.log(data);
    } else {
      console.log('エラー:', xhr.status);
    }
  }
};

/* 進捗の取得（Fetch APIにはない機能） */
xhr.onprogress = (e) => {
  if (e.lengthComputable) {
    console.log(Math.round(e.loaded / e.total * 100) + '%');
  }
};

/* リクエスト送信 */
xhr.send(); /* GETの場合はnullまたは省略 */

/* POSTの場合 */
xhr.open('POST', '/api/users', true);
xhr.setRequestHeader('Content-Type', 'application/json');
xhr.send(JSON.stringify({ name: 'Alice' }));


/* ===== Fetch API（モダンな書き方）===== */
async function getData() {
  try {
    const res  = await fetch('https://api.example.com/data');
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();
    console.log(data);
  } catch (e) {
    console.log('エラー:', e);
  }
}

⚠️ XHR / Fetch の注意点
・同一オリジンポリシーにより、異なるオリジンへのリクエストは制限されます（CORS設定が必要）
・Fetch API では 404・500 などの HTTP エラーは例外にならず、response.ok が false になります
・XHR の open() の第3引数 true は非同期モードを意味します（false は同期で非推奨）

② WebSocket API

重要ポイント②（前半）：WebSocketでサーバーとブラウザ間の双方向リアルタイム通信を実現する
WebSocket は HTTP のハンドシェイクで接続を確立した後、 ws:// または wss://（暗号化） プロトコルで 全二重（双方向）の持続的な接続を維持します。 HTTPのように都度接続・切断を繰り返さないため、 低遅延・高頻度なリアルタイム通信に適しています。

WebSocket の接続フロー

ブラウザ
→ HTTP Upgrade →
サーバー
→ 101 Switching →
ws:// 接続確立
↔ 双方向通信 ↔
持続的接続

WebSocket の主なイベント・メソッド・プロパティ

種別名前説明
メソッド send(data) サーバーにデータを送信（文字列・ArrayBuffer・Blob）
close(code, reason) 接続を閉じる。コードと理由を指定できる
イベント onopen 接続確立時に発火
onmessage メッセージ受信時に発火。event.data にデータが入る
onerror エラー発生時に発火
onclose 接続が閉じた時に発火。event.code / event.reason で理由を確認
プロパティ readyState 接続状態（0:CONNECTING / 1:OPEN / 2:CLOSING / 3:CLOSED）
bufferedAmount 送信待ちのデータ量（バイト） 
/* WebSocket 接続の作成 */
const ws = new WebSocket('wss://echo.websocket.org');
/* wss:// = 暗号化あり（HTTPS相当）、ws:// = 暗号化なし */

/* 接続確立時 */
ws.onopen = (event) => {
  console.log('接続確立');
  ws.send('Hello, Server!'); /* 文字列を送信 */
};

/* メッセージ受信時 */
ws.onmessage = (event) => {
  console.log('受信:', event.data); /* event.data にデータが入る */
};

/* エラー発生時 */
ws.onerror = (error) => {
  console.log('エラー:', error);
};

/* 接続が閉じた時 */
ws.onclose = (event) => {
  console.log('切断:', event.code, event.reason);
};

/* 接続を閉じる */
ws.close(1000, '正常終了');

/* readyState の値 */
WebSocket.CONNECTING /* 0: 接続中 */
WebSocket.OPEN        /* 1: 接続済み（送受信可能） */
WebSocket.CLOSING     /* 2: 切断中 */
WebSocket.CLOSED      /* 3: 切断済み */

③ Server-Sent Events（SSE）

重要ポイント②（後半）：Server-Sent Eventsでサーバーからクライアントへの一方向リアルタイム通信を実現する
Server-Sent Events（SSE）は、サーバーからクライアントへの一方向のリアルタイム通信を 通常のHTTP接続上で実現するAPIです。 EventSource オブジェクトを使い、サーバーが text/event-stream 形式でデータを送り続けます。 WebSocketより実装が簡単で、自動再接続機能も内蔵しています。

SSE vs WebSocket の比較

項目Server-Sent EventsWebSocket
通信方向サーバー → クライアント（一方向）双方向（全二重）
プロトコルHTTP（text/event-stream）ws:// / wss://
自動再接続内蔵（自動）自前実装が必要
実装の複雑さシンプルやや複雑
データ形式テキストのみテキスト・バイナリ両対応
向いている用途通知・株価・ニュースフィードチャット・ゲーム・共同編集

SSE のデータフォーマット（サーバー側）

/* サーバーが送信する text/event-stream 形式 */
/* Content-Type: text/event-stream を返す必要がある */

/* 基本形式：data: フィールドのみ */
data: Hello, World!
                          ← 空行でイベント区切り
/* 複数フィールドの指定 */
id:    42               ← イベントID（再接続時のLastEventIDに使われる）
event: stock-update    ← カスタムイベント名
data:  {"price": 1500}  ← データ（JSON文字列も可）
retry: 3000            ← 再接続間隔（ms）

EventSource API の使い方

/* EventSource の作成 */
const es = new EventSource('/events');
/* withCredentials: Cookie を送信する場合 */
const es2 = new EventSource('/events', { withCredentials: true });

/* 接続確立時 */
es.onopen = () => console.log('SSE接続確立');

/* デフォルトイベント（event: フィールドなし）の受信 */
es.onmessage = (event) => {
  console.log('data:',    event.data);    /* データ */
  console.log('lastEventId:', event.lastEventId); /* イベントID */
};

/* カスタムイベントの受信（event: stock-update） */
es.addEventListener('stock-update', (event) => {
  const data = JSON.parse(event.data);
  console.log('株価更新:', data.price);
});

/* エラー・切断時（自動再接続される） */
es.onerror = (e) => {
  if (es.readyState === EventSource.CLOSED) {
    console.log('接続が閉じました');
  }
};

/* 手動で接続を閉じる（自動再接続を止める） */
es.close();

/* readyState の値 */
EventSource.CONNECTING /* 0: 接続中（再接続中も含む） */
EventSource.OPEN        /* 1: 接続済み */
EventSource.CLOSED      /* 2: 切断済み */

④ WebRTC（Web Real-Time Communication）

重要ポイント③：WebRTCでビデオチャットのようなブラウザ間リアルタイムコミュニケーションを実現する
WebRTC はブラウザ間（P2P）でビデオ・音声・データを サーバーを介さずリアルタイムに通信するAPIです。 ビデオ通話・音声通話・ファイル共有・画面共有などを実現します。 ただし接続確立のためにシグナリングサーバー（SDP・ICE候補の交換）が必要です。

WebRTC の P2P 接続フロー

ブラウザA（発信側）
① getUserMedia()
② RTCPeerConnection作成
③ createOffer()
④ setLocalDescription()
⑦ setRemoteDescription()
SDP交換 ↔ ICE候補 （シグナリング
サーバー経由）
ブラウザB（受信側）
⑤ setRemoteDescription()
⑥ createAnswer()
⑥ setLocalDescription()
⑧ P2P接続確立！

WebRTC の主なAPI

getUserMedia()
カメラ・マイクへのアクセスを要求し、MediaStream を取得する
RTCPeerConnection
P2P接続を管理するメインのオブジェクト。SDP・ICEの処理を担う
createOffer() / createAnswer()
SDP（Session Description Protocol）の生成。発信側がOffer、受信側がAnswer
setLocalDescription()
自分のSDPをセット。ICE候補の収集が始まる
setRemoteDescription()
相手のSDPをセット
RTCDataChannel
P2Pでテキスト・バイナリデータを送受信するチャンネル
ICE（Interactive Connectivity Establishment）
NAT越えのための接続経路探索プロトコル。STUN/TURNサーバーを使う
SDP（Session Description Protocol）
メディアの種類・コーデック・IPアドレスなどの接続情報を記述するフォーマット
/* ===== Step 1：カメラ・マイクへのアクセス ===== */
const stream = await navigator.mediaDevices.getUserMedia({
  video: true,  /* カメラを使用 */
  audio: true   /* マイクを使用 */
});
/* video要素に映像を表示 */
document.getElementById('localVideo').srcObject = stream;


/* ===== Step 2：RTCPeerConnection の作成 ===== */
const pc = new RTCPeerConnection({
  iceServers: [
    { urls: 'stun:stun.l.google.com:19302' } /* STUNサーバー */
  ]
});

/* ストリームのトラックを追加 */
stream.getTracks().forEach(track => pc.addTrack(track, stream));

/* ICE候補が見つかったらシグナリングサーバーに送る */
pc.onicecandidate = (event) => {
  if (event.candidate) {
    signalingServer.send(JSON.stringify({
      type: 'ice-candidate',
      candidate: event.candidate
    }));
  }
};

/* 相手のストリームを受信 */
pc.ontrack = (event) => {
  document.getElementById('remoteVideo').srcObject = event.streams[0];
};


/* ===== Step 3：発信側 - Offer の作成と送信 ===== */
const offer = await pc.createOffer();
await pc.setLocalDescription(offer);
signalingServer.send(JSON.stringify({ type: 'offer', sdp: offer }));


/* ===== Step 4：受信側 - Answer の作成と送信 ===== */
await pc.setRemoteDescription(offer);  /* 相手のOfferをセット */
const answer = await pc.createAnswer();
await pc.setLocalDescription(answer);
signalingServer.send(JSON.stringify({ type: 'answer', sdp: answer }));


/* ===== RTCDataChannel：P2Pデータ通信 ===== */
const dc = pc.createDataChannel('chat');
dc.onopen    = () => dc.send('Hello P2P!');
dc.onmessage = (e) => console.log('P2P受信:', e.data);

⚠️ WebRTC の注意点
・シグナリングサーバー（WebSocketなどで実装）は自前で用意する必要があります
・NAT越えのために STUN / TURN サーバーが必要です
