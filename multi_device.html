① CSSスプライト（CSS Sprites）

重要ポイント①：CSSスプライトは、複数の画像を1つにまとめることで、ページ表示速度を向上することができる手法
複数の小さな画像（アイコンなど）を1枚の画像ファイルにまとめ、 background-position で表示位置を切り替えることで、 HTTPリクエスト数を減らしてページの表示速度を向上させます。

✅ CSSスプライトのメリット
・HTTPリクエスト数を削減 → ページ表示速度の向上
・画像ファイルの管理が1ファイルにまとまる

⚠️ 現代での注意点
HTTP/2 では複数リクエストの並列処理が効率化されたため、 スプライトの恩恵は以前より小さくなっています。 現代では SVGスプライト や アイコンフォント（Font Awesome など） も広く使われています。

② 高解像度画面向け対応（Retina ディスプレイ）

重要ポイント②：Retina ディスプレイでは、4デバイスピクセルが1CSSピクセルとして扱われる
Retina ディスプレイ（高解像度ディスプレイ）では、 物理的なピクセル（デバイスピクセル）が CSS で扱うピクセル（CSSピクセル）より多く存在します。 デバイスピクセル比（DPR）が2の場合、1CSSピクセル = 2×2 = 4デバイスピクセルです。

デバイスピクセル比（DPR）の仕組み

通常ディスプレイ（DPR: 1）
1CSSピクセル = 1デバイスピクセル
2×2 CSS = 2×2 デバイス
Retina（DPR: 2）
1CSSピクセル = 4デバイスピクセル
2×2 CSS = 4×4 デバイス
/* ===== 高解像度ディスプレイ向けの画像対応 ===== */

/* 方法①：メディアクエリで高解像度用画像を指定 */
.logo {
  background-image: url("logo.png");      /* 通常解像度用 */
  background-size: 100px 50px;
}
@media (min-resolution: 2dppx) {
  .logo {
    background-image: url("logo@2x.png");  /* 2倍解像度用 */
  }
}

/* 方法②：srcset 属性で解像度に応じた画像を指定 */

<img
  src="logo.png"
  srcset="logo.png 1x, logo@2x.png 2x, logo@3x.png 3x"
  alt="ロゴ"
  width="100" height="50">

<!-- 方法③：SVG を使う（解像度に依存しない） -->
<img src="logo.svg" alt="ロゴ" width="100" height="50">
DPR（デバイスピクセル比）1CSSピクセルのデバイスピクセル数対応画像代表デバイス
1x（DPR: 1）1×1 = 1ピクセル通常画像一般的なPC
2x（DPR: 2）2×2 = 4ピクセル@2x 画像Retina Mac・iPhone
3x（DPR: 3）3×3 = 9ピクセル@3x 画像iPhone Pro・高解像度Android
⚠️ 重要ポイント②の補足
「4デバイスピクセルが1CSSピクセル」とは、 DPR が2のとき、1CSSピクセルが縦2×横2 = 4デバイスピクセルで構成されることを指します。 通常の画像をそのまま表示すると、Retina ディスプレイでは引き伸ばされてぼやけて見えるため、 2倍サイズの画像を用意して対応します。

④ スタンドアローンモード（Standalone Mode）

スタンドアローンモードとは、Webサイトをホーム画面から起動したとき、 ブラウザのアドレスバーやナビゲーションバーを非表示にして、 ネイティブアプリのような全画面表示にするモードです。 Web App Manifest または meta タグで設定します。 

<!-- iOS：meta タグで指定 -->
<meta name="apple-mobile-web-app-capable"
      content="yes">
<meta name="apple-mobile-web-app-status-bar-style"
      content="black-translucent">
<meta name="apple-mobile-web-app-title"
      content="アプリ名">

<!-- Web App Manifest（manifest.json）で指定 -->
<link rel="manifest" href="manifest.json">

// manifest.json の例
{
  "name": "My Web App",
  "short_name": "MyApp",
  "display": "standalone",  // スタンドアローンモード
  "start_url": "/",
  "background_color": "#ffffff",
  "theme_color": "#38a169",
  "icons": [
    {
      "src": "icon-192.png",
      "sizes": "192x192",
      "type": "image/png"
    }
  ]
}
display の値説明
standaloneブラウザUIを非表示にしてアプリのように表示
fullscreenステータスバーも含めて完全な全画面表示
minimal-ui最小限のブラウザUIを表示
browser通常のブラウザ表示（デフォルト）
✅ PWA（Progressive Web App）との関係
スタンドアローンモードは PWA の重要な要素の1つです。 Web App Manifest・Service Worker・HTTPS の組み合わせにより、 ネイティブアプリに近い体験を Web で実現できます。

⑤ a 要素での電話発信・SMS送信

href 属性に tel: スキームを使うことで、 スマートフォンでタップしたときに電話発信できるリンクを作れます。 同様に sms: で SMS 送信、mailto: でメール送信も可能です。 

<!-- 電話発信リンク -->
<a href="tel:0120-123-456">📞 0120-123-456</a>

<!-- 国際電話番号形式（推奨） -->
<a href="tel:+81-90-1234-5678">📞 090-1234-5678</a>

<!-- SMS 送信リンク -->
<a href="sms:090-1234-5678">💬 SMS を送る</a>

<!-- SMS 本文を事前入力（iOS / Android で書式が異なる） -->
<a href="sms:090-1234-5678?body=お問い合わせです">💬 SMS</a>

<!-- メール送信リンク -->
<a href="mailto:info@example.com">✉️ メールを送る</a>

<!-- メール：件名・本文も指定 -->
<a href="mailto:info@example.com?subject=お問い合わせ&body=こんにちは">
  ✉️ お問い合わせメール
</a>
デモ（実際にタップ/クリックで動作します）
📞 電話発信 💬 SMS送信 ✉️ メール送信
⚠️ tel: リンクの注意点
・PCブラウザでは電話アプリが起動する場合があります（Skype など）
・電話番号の表示テキストと href の番号を一致させましょう
・国際電話番号形式（+81 など）を使うと国際対応できます

⑥ async 属性 / defer 属性

重要ポイント③：script 要素でHTMLパース処理を中断させずにJavaScriptを読み込むためには、async 属性 / defer 属性を使う
通常の <script> タグはHTMLのパース（解析）を中断してスクリプトを実行します。 async または defer 属性を使うことで、 HTMLのパースを止めずにスクリプトを読み込めます。

<!-- 通常（HTMLパースを中断してJSを読み込み・実行） -->
<script src="script.js"></script>

<!-- async：HTMLパースと並行してJSを読み込み、読み込み完了次第すぐ実行 -->
<script src="script.js" async></script>

<!-- defer：HTMLパースと並行してJSを読み込み、HTML解析完了後に実行 -->
<script src="script.js" defer></script>
属性読み込み実行タイミング実行順序主な用途
なし（通常） HTMLパースを中断 読み込み完了後すぐ 記述順 インラインスクリプト
async HTMLパースと並行 読み込み完了後すぐ（パース中でも） 読み込み完了順（不定） 他スクリプトに依存しない独立したスクリプト（広告・アクセス解析など）
defer HTMLパースと並行 HTMLパース完了後（DOMContentLoaded の直前） 記述順を保証 DOM操作を行うスクリプト・複数スクリプトの依存関係がある場合
✅ async / defer の使い分けのポイント
・async：他のスクリプトに依存しない独立したスクリプト（Google Analytics など）
・defer：DOM を操作するスクリプト・複数スクリプト間に依存関係がある場合
・type="module" を指定したスクリプトはデフォルトで defer と同様の動作をします
⚠️ async / defer の注意点
・async と defer は外部スクリプト（src 属性あり）にのみ有効です
・インラインスクリプト（<script> タグ内に直接記述）には効果がありません
・async と defer を両方指定した場合は async が優先されます
